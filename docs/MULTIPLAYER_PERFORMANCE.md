# 战术地图多人性能

ESPoints 协议 `13` 面向约 100 名在线玩家设计。客户端和服务端必须同时替换
Espetro 与 ESPoints JAR；协议 `13` 不兼容旧客户端。

## 分级底图

- Espetro 激活地图时提供冻结 PNG 的 SHA-256、宽高和只读内容；ESPoints 不写入 `EsWorld`。
- 服务端以双三次缩放和轻度边缘锐化在后台生成 512×512 分级 PNG 瓦片，缓存目录为
  `config/espoints/cache/tactical-map/<sha256>-p2/`。原图 L0 不重采样，最低清晰度优先预热。
- 打开地图只改变可见性和订阅；不会在渲染线程读取文件、解码整张 PNG 或上传整图纹理。
- 客户端先请求基础可见瓦片及基础 LOD 的一圈预取；平衡/高清档在视野稳定 250 ms 后，
  按上一层完整就绪的顺序细化一/两层，细化层不预取。后台完成 PNG 解码后，渲染线程只负责
  注册线性过滤、无 GPU mipmap 的纹理；未就绪时保留低级预览或纯色底图。
- 默认客户端纹理 LRU 为 64 MiB，服务端编码瓦片 LRU 为 32 MiB，磁盘预算为
  512 MiB。当前视野的层级估算超过客户端预算 75% 时自动降低细节；地图切换或断线会释放
  纹理、待处理请求和会话缓存。
- 单玩家瓦片平均预算为 256 KiB/s，全服为 4096 KiB/s；令牌桶允许最多 8 秒的受限突发，
  以便单个最大 2 MiB 瓦片可以完成传输。

## 动态同步

- V 键地图、部署界面嵌入地图和火炮选点地图自动订阅；客户端每 4 秒续期，
  停止渲染后服务端最多 6 秒自动退订。
- 未订阅玩家不接收每 0.5 秒一次的位置帧。
- 身份表只在加入、离开、小队/组长/指挥官身份变化时发送；位置帧使用会话内
  16 位 ID、1/8 格定点 X/Z 和 8 位朝向，不重复姓名、UUID 或小队文本。
- 玩家和战术状态按阵营裁剪。据点、兵站、主基地、Rally、原部署点、补给站和标点
  采用事件增量或 revision 快照；据点总览只在界面请求时返回。
- Rally 传输绝对下一波时间，客户端本地计算倒计时，不因秒数变化反复广播。
- 标点新增/删除使用最多 64 项的有界增量包；完整快照仅在订阅或恢复时发送。

自动化最坏模型中，100 个位置条目每 0.5 秒发送给 100 个订阅者时，动态位置流量
低于 250 KiB/s，单客户端低于 3 KiB/s。瓦片流量由独立预算限制。

## CPU 与内存边界

- 据点按区块索引，每名玩家只检查所在区块的候选据点。
- 位置、兵站、据点与标点只处理活跃集合；低频兜底不强制加载区块，也不执行
  `getAllEntities()` 全世界扫描。
- 同一瓦片的并发生成/读取合并为一个任务；图片解码和磁盘 I/O 不在服务器主线程执行。
- 包含列表长度、字符串、坐标、图片像素、瓦片编号、压缩大小、会话和请求频率上限。
- 50 局激活/双重清理自动化测试验证逻辑客户端状态归零；实际整合服仍应结合
  Spark/JFR 检查其他模组、实体量、视距和磁盘造成的尖峰。
